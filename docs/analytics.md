# Google Analytics 4 の旧設定と導入記録

現在のサイトではGoogle Analyticsを無効にしています。以下は旧構成の記録です。
公開サイトへの反映は [公開手順の「Google Analyticsの無効化」](deployment.md#google-analyticsの無効化) を参照してください。

## 今回の実装と完了条件

日英の全21コンテンツページに、共通のGA4設定と読み込み処理を追加しました。
旧URLの転送ページ2枚は計測せず、転送先だけを計測します。
英語ホームだけにあったGoogleタグを共通処理に置き換え、
以前の測定ID `G-RHZJ84JYRR` を `analytics-config.js` に引き継ぎました。
既存のGA4設定を継続するため、プロパティやストリームの新規作成は不要です。
Google管理画面へのアクセスは行っていないため、同じIDがご自身のウェブストリームに表示されることを公開前に確認してください。

**ローカルの設定は済んでいます。公開作業と本番GA4での受信確認は未実施です。**
既存プロパティの確認 → 本番URL・許可ホストの確認 → 公開 → 実データの確認の順に進めてください。
公開サイトへの訪問で、同意後に `page_view` がGA4へ届くことを確認したら導入完了です。

| ファイル | 役割 |
| --- | --- |
| `public/assets/js/analytics-config.js` | 測定IDと計測を許可するホスト名 |
| `public/assets/js/analytics.js` | 同意状態の保存、同意後のGoogleタグ読み込み |
| `public/assets/css/analytics.css` | 日英の同意パネルと設定ボタンの表示 |
| 各ページのHTML | 共通設定・処理・CSSの読み込み |
| `public/assets/js/site-shell.js` | フッターの「アクセス解析の設定」ボタン |

## まず行うこと: 以前のGitHub Pagesの設定を引き継ぐ

- [ ] [Google Analytics](https://analytics.google.com/) に以前利用していたGoogleアカウントでログインします。
- [ ] 以前のポートフォリオを計測していたプロパティを選択します。過去のレポートが残っていることも確認します。
- [ ] 「管理」→「データの収集と修正」→「データストリーム」から、GitHub Pages用に作成したウェブストリームを開きます。
- [ ] 測定IDが `G-RHZJ84JYRR` と一致することを確認します。違う場合は、この設定ファイルも管理画面の正しいIDへ変更します。
- [ ] 独自ドメインへ移行する場合は、ウェブストリーム詳細の編集から「ウェブサイトのURL」を `https://kentashiki.com` など実際の本番URLへ更新します。測定IDは継続して使います。
- [ ] 拡張計測機能の設定を確認します。詳しくは下記の手順2を参照してください。
- [ ] 独自ドメインを本番にする場合は、既定の `allowedHosts` が一致していればそのまま使います。
- [ ] GitHub Pagesも引き続き計測する場合は、下記「GitHub Pagesも計測する場合」に従って `kentashiki.github.io` を追加します。
- [ ] 手順4の公開と、手順5の本番確認を実施します。

同じプロパティ・ストリームを使えば、過去のデータを保持したまま、新しいサイトのデータを同じ場所で確認できます。
ドメイン移行時はホスト名やページパスが変わるため、レポート上でも区別して確認してください。
これまでタグのなかったページの閲覧を遡って復元することはできません。
また、同意後だけ計測する方式への変更によって訪問数が変わるため、変更前後の数値は単純比較しないでください。

参考: [測定IDの確認](https://support.google.com/analytics/answer/12270356?hl=ja)、

## 1. 新規の場合のみ: Google側でアカウントとプロパティを作る

既存の設定を引き継ぐ今回の作業では、この手順とストリームの新規作成は不要です。

- [ ] [Google Analytics](https://analytics.google.com/) に、今後管理するGoogleアカウントでログインします。
- [ ] 初回なら「測定を開始」。既存アカウントがあれば「管理」→「作成」からプロパティを作成します。
- [ ] アカウント名は例として `Kenta Shiki`、プロパティ名は `Kenta Shiki Portfolio` にします。
- [ ] レポートのタイムゾーンを「日本」、通貨を「日本円」にします。
- [ ] 業種・規模・ビジネス目標は実態に合わせて選択します。
- [ ] データ共有設定を確認し、画面の利用規約を確認して進みます。

アカウントは管理用の入れ物、プロパティはこのサイトの分析単位です。
この静的サイトではGoogle Tag Manager、Google CloudのAPI設定、OAuth認証、秘密のAPIキーは不要です。

参考: [Google公式のセットアップ手順](https://support.google.com/analytics/answer/9304153?hl=ja)

## 2. 新規の場合のストリーム作成・既存ストリームの拡張計測確認

- [ ] データ収集のプラットフォームで「ウェブ」を選びます。
- [ ] ウェブサイトURLに実際の本番URLを入力します。独自ドメインで公開する場合の例は `https://kentashiki.com` です。
- [ ] ストリーム名を `Portfolio Web` などにして作成します。
- [ ] 「拡張計測機能」を有効にします。設定の歯車から、ページビュー・スクロール・離脱クリック・ファイルのダウンロード・フォーム操作を確認します。
- [ ] サイト内検索はこのサイトにないので無効にして構いません。動画計測は、対応するYouTube埋め込みなどの条件を満たす場合のみ有効です。
- [ ] 表示される **測定ID `G-…`** をコピーします。数字だけのプロパティIDやストリームIDとは異なります。

あとから確認する場合は、「管理」→「データの収集と修正」→「データストリーム」→作成したウェブストリームを開きます。
表示されるメニュー名はGoogle側の更新で多少変わることがあります。

Googleの画面に表示されるタグのHTMLを各ページへ追加する必要はありません。
今回の共通処理がタグを読み込むため、別に追加すると二重計測につながります。

参考: [拡張計測機能のイベントと条件](https://support.google.com/analytics/answer/9216061?hl=ja)

## 3. このサイトへ測定IDを設定する

`public/assets/js/analytics-config.js` には、以前のコードにあった測定IDを設定済みです。
Google管理画面で確認したIDが異なる場合にだけ、正しい値へ置き換えてください。

```js
window.portfolioAnalyticsConfig = {
  measurementId: "G-RHZJ84JYRR",
  allowedHosts: ["kentashiki.com", "www.kentashiki.com"],
};
```

- [ ] `measurementId` が既存ウェブストリームの測定IDと一致することを確認します。
- [ ] `allowedHosts` と実際に公開するドメインが一致することを確認します。`https://` や `/` は含めません。
- [ ] IDを後日差し替える際は、各HTMLにある `analytics-config.js?v=20261019b` の版番号も更新して、古い設定のキャッシュを避けます。

測定IDは公開して使う値です。パスワードやGoogleアカウントの認証情報は書き込みません。
設定が空・形式不正・許可されていないホスト・HTTPS以外の場合は、Googleタグも同意パネルも読み込みません。

### GitHub Pagesも計測する場合

既定では独自ドメインだけを計測し、`kentashiki.github.io/portfolio/` はプレビューとして除外します。
Pagesを本番として使う場合、または両方を同じプロパティで分析したい場合は、次のように追加します。

```js
allowedHosts: ["kentashiki.com", "www.kentashiki.com", "kentashiki.github.io"],
```

Pagesだけを公開するなら、ストリームのURLも `https://kentashiki.github.io/portfolio/` にします。
複数ホストのデータを同じプロパティへ集めた場合、GA4でホスト名も確認して区別してください。
この設定だけで複数ドメイン間の訪問者が同一人物として統合されるわけではありません。

- [ ] GitHub Pagesは `main` に変更をpushし、公開ワークフローの成功を確認します。

## 5. 本番で計測を確認する

### まずリアルタイムで確認

- [ ] 拡張機能の影響を受けにくいブラウザー環境で、本番サイトを新しく開きます。
- [ ] 同意パネルの「同意する」を押します。「同意しない」のままでは計測されません。
- [ ] GA4の「レポート」→「リアルタイム」を開き、自分の訪問と `page_view` を確認します。
- [ ] 日本語ホーム、英語ホーム、Work詳細、Outputs、Contactへ移動して、それぞれのページが記録されることを確認します。
- [ ] PDFへのリンク、外部リンクをクリックし、拡張計測を有効にしたイベントが届くことを確認します。

### 詳細はDebugViewで確認

本番ページのURLに `?analytics_debug=1` を付けると、このページでの計測だけデバッグモードになります。
既に `?` があるURLでは `&analytics_debug=1` を追加します。

```text
https://kentashiki.com/ja/?analytics_debug=1
```

- [ ] このURLを開いて解析に同意します。
- [ ] 「管理」→「データの表示」→「DebugView」で、その端末のイベントを確認します。
- [ ] ページを一度読み込んだときに、`page_view` が重複していないことを確認します。
- [ ] 他のページもデバッグする際は、そのURLにもパラメーターを付けます。通常のリンク移動では引き継ぎません。
- [ ] 確認後はパラメーターを外します。通常のレポートへの反映はリアルタイムより遅れるため、直ちに表示されない場合は時間を置きます。

ブラウザーの開発者ツールを使える場合は、Networkでも確認できます。
新しいブラウザー環境で、同意前・拒否後に `googletagmanager.com/gtag/js` やGAの収集リクエストがなく、
同意後にタグと `g/collect` リクエストが現れることを確認します。
フッターの「アクセス解析の設定」から拒否へ変更すると、計測を停止してページを再読み込みします。

参考: [DebugViewの公式案内](https://support.google.com/analytics/answer/7201382?hl=ja)、
[ページビューの送信](https://developers.google.com/analytics/devguides/collection/ga4/views?hl=ja)

## 6. このポートフォリオで見る指標

訪問数だけでなく、研究・プロダクトへの関心や、協業につながる接点が増えているかを見ます。

| 確認したいこと | GA4で使うデータ | 解釈上の注意 |
| --- | --- | --- |
| どこから来たか | トラフィック獲得、参照元 / メディア | SNSやイベント別のリンクにはUTMを付けると比較しやすい |
| どの研究・プロダクトに関心があるか | ページとスクリーン、`/work/…` と `/ja/work/…` | 閲覧数とエンゲージメントを併せて確認 |
| 資料を見ようとしたか | `file_download` | PDFリンク等のクリックであり、ダウンロード完了や読了ではない |
| 外部プロフィール・デモに進んだか | `click`、リンク先URL | 拡張計測の離脱クリックが対象。内部リンクはページ遷移で確認 |
| 連絡先を見たか | Contactページ閲覧 | 問い合わせの実数は受信メールで確認 |
| 日英どちらが使われたか | ページパスの `/ja/` の有無 | GAの「言語」はブラウザー設定で、閲覧したサイトの言語とは異なる |

UTMの例:

```text
https://kentashiki.com/?utm_source=linkedin&utm_medium=social&utm_campaign=portfolio
```

氏名、メールアドレス、お問い合わせ本文などをURLやUTMへ含めないでください。
GoogleタグはページURLも扱います。フォーム入力値を独自イベントへ追加することも避けてください。

## 同意とデータの取り扱い

### このサイトでの運用方針

海外の研究者・企業も積極的に公開対象とするため、現在は訪問者の事前同意を得る方式を維持します。
これは、日本のすべてのサイトで同意バナーが義務という意味ではありません。
日本の個人情報保護委員会は、個人関連情報の第三者提供で常に同意確認が必要なわけではなく、
提供先が個人データとして取得することが想定される場合に原則として確認が必要と説明しています。
この条件だけから、このサイトのすべての閲覧者について同意不要とは判断できません。

欧州ではアクセス解析用Cookieにも事前同意が必要となる場合があり、同意免除には条件があります。
GoogleのEUユーザー同意ポリシーも、適用対象の製品・契約について、EEA・英国・スイスの利用者に
法的に必要なCookie同意を取得することを求めています。
単に英語ページがあることや欧州からアクセスできることだけでGDPRの適用が確定するわけではありませんが、
提供対象や行動の追跡内容を踏まえた判断が必要です。現在のGA4設定で免除を満たすことは確認していません。

バナーの表示を減らすには、アクセス元の地域に応じて同意が必要な地域だけ表示する構成が候補です。
このリポジトリには信頼できる地域判定をまだ組み込んでいないため、現在は全地域で同意を確認します。
`/ja/` の有無やブラウザーの言語だけで、居住地域や適用法令を判断することはしません。
また、Cookieを保存しない設定に変えるだけで、あらゆる地域で同意が不要になるわけではありません。

判断に使った公式資料:

- [個人情報保護委員会: 個人関連情報の第三者提供と同意確認](https://www.ppc.go.jp/all_faq_index/faq1-q8-3/)
- [Google: EUユーザー同意ポリシー](https://www.google.com/about/company/user-consent-policy/)
- [CNIL: アクセス解析ツールの同意免除条件](https://www.cnil.fr/fr/cookies-et-autres-traceurs/regles/cookies-solutions-pour-les-outils-de-mesure-daudience)
- [EDPB: GDPRの地理的適用範囲](https://www.edpb.europa.eu/our-work-tools/our-documents/guidelines/guidelines-32018-territorial-scope-gdpr-article-3-version_en)

- 計測への同意前・拒否中はGoogleタグを読み込まないBasic Consent Modeです。
- 同意パネルに利用目的、Cookie、送信情報、Googleのデータ利用ページを案内しています。
- 同意・拒否はこのブラウザーのローカルストレージに180日間保存します。ホストが異なると別の選択になります。
- フッターから変更できます。保存をブラウザーが禁止している場合、選択は現在のページだけに適用されます。
- Google Signalsと広告パーソナライズの利用をコードで無効にしています。広告用の同意も拒否にしています。
- 拒否へ変更しても過去に送ったデータや既存Cookieを削除する操作にはなりません。
- 同意した訪問者のうち、ブラウザー等で計測が遮断されない訪問だけが対象です。GAの訪問数はサイトの総アクセス数と一致しません。

Google側でもGoogle Signalsや広告連携を目的なく有効にせず、ストリームの「データの秘匿化」で
メールアドレスや必要なクエリパラメーターの秘匿設定を確認してください。

参考: [Basic Consent Mode](https://developers.google.com/tag-platform/security/guides/consent?consentmode=basic)、
[Google Analyticsのプライバシー開示方針](https://support.google.com/analytics/answer/7318509?hl=ja)

## 計測されない場合

1. `measurementId` が空や説明用のIDになっていないか確認します。
2. 現在のホスト名が `allowedHosts` に入っていて、HTTPSで開いているか確認します。
3. フッターから解析への同意を確認します。拒否中はイベントが届きません。
4. 更新した設定・処理・CSS・全HTMLが本番へアップロードされているか確認します。
5. ブラウザーのキャッシュを更新します。ID変更時は設定ファイルの版番号も更新します。
6. 広告ブロッカーやブラウザーの追跡防止設定による遮断を確認します。
7. GA4で正しいプロパティとウェブストリームを開いているか確認します。
8. 本番のNetwork、リアルタイム、DebugViewで順に確認します。

## 実装の確認記録

実施済みの確認:

- JavaScriptの構文、変更ファイルの差分、全21ページの共通ファイル参照を確認。
- ブラウザーで同意前の未読み込み、拒否の保存、同意後の起動、再同意時の重複防止、撤回後の停止を確認。
- 日英表示、同意の有効期限、不正な保存データ、375px幅の表示、全21ページの設定ボタンを確認。
- 測定ID未設定、HTTP、許可外ホストでタグと同意UIが無効になることを確認。
- XServer用の全サイトZIPに追加ファイルが含まれることを確認。

ブラウザー検証ではGoogleのライブラリを模擬に置き換え、実際のGoogleへのイベント送信は行っていません。
以前のコードから測定IDを共通設定へ引き継ぎ、設定ファイルのキャッシュ用版番号も更新済みです。
Google管理画面でのID照合・URL変更、公開作業、本番GA4での受信確認は未実施です。
ローカルの検証で確認できるのは、各ページの接続、同意前後の処理、タグの起動回数などです。
GA4での受信成功は、上記の本番確認を終えるまで未確認として扱います。
